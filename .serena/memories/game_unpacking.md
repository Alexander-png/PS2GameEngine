## CFG + stack model (2026-10-17)
- tools/gmcfg.py (basic blocks + abstract operand-stack interpretation with sizes + known consts), tools/cfgtrace.py <win> <entry> [lo hi] (disasm with per-insn stack state; use it to debug misses).
- Verified consistent (every join one depth, no underflow): Undertale 6108/6108 (85,584 blocks, max depth 17), Yellow 13776/13786, DELTARUNE root 390/390, ch1 1846/1852, ch2 6948/6979, ch3 9613/9666, ch4 12445/12505, ch5 18113/18349. Remaining ~0.1-1.3% not modeled yet (use interpreter fallback or fix later).
- Goto offsets are 23-bit signed words (bit22 sign); popenv with low24==0xF00000 = break-out marker (no target).
- Stack is BYTE-sized for dup: entry sizes v=16 (variant), i/b/f/e=4, d/l=8; `dup.t n` copies (n+1)*size(t) bytes; dup with 0x80 in bits 15..8 = swap (no net depth change).
- GMS2 (bytecode>=16) stack-instance access: operands carry an instance MARKER value; marker -9 means an instance value sits below it. push var vt 0x80 pops 1 (+1 if top==-9); pop var vt 0x80 pops 2 (+1 if -9 on top OR just below the value - two layouts: [value,inst,-9] and [inst,-9,value]); arrays (vt 0x00): push pops 2(+1 if below==-9), pop pops 3(+1). vt 0x10/0x90 = pushaf/popaf (push: pops 2 pushes array ref). itype -9 explicit stacktop: push pops 1 pushes 1, pop pops 2. pushenv pops 1 (+1 if top==-9). callv pops argc+2 (function, instance, args), pushes 1. Break sub-ops (pops,pushes): -1 chkindex(0,0), -2 pushaf(2,1), -3 popaf(3,0), -4 pushac(1,1), -5 setowner(1,0), -6 isstaticok(0,1), -7 setstatic(0,0), -8 savearef, -9 restorearef (0,0), -10 chknullish(0,0), -11 pushref(0,1).

## Video micro-freeze cause (found + fixed)
- vidplay instrumented (per-frame decode / sound-clock RPC time / GS upload / ring underruns / reader stalls, stall classification). Before: ch3 66-87 dropped frames, ALL stalls = the EE->engsnd sstat RPC taking 150-165 ms, once per audio ring half refill (every ~1.3 s).
- Cause: IOP priority inversion. engsnd stream thread (prio 36) does the blocking disc read/SPU DMA and starves the RPC server thread (was prio 40). NOT the EE (reader prio change had no effect), NOT decode (8 ms), NOT GS (0), NOT ring underrun. Slicing the IOP reads with DelayThread made it worse (reverted).
- Fix: engsnd server thread priority 30 (above stream 36). Result in PCSX2: ch3 1224/1224 shown, 0 dropped, 0 stalls; ch5 727/727, 0 dropped.
- Design rule: every IOP RPC-serving thread must outrank stream/disc threads; EE should also avoid blocking RPC on the frame path (consider NOWAIT + extrapolated audio clock). Real HW still to test: DVD seeks between video file and audio file (consider interleaving A/V into one file or larger read-ahead).
