New PS2 homebrew game engine project (folder was empty when registered, 2026-10-16). Fill in after onboarding.

- Hardware docs: mem:hardware_docs
- Toolchain (changed 2026-10-17): own vendored SDK. Compilers still from PS2DEV=/usr/local/ps2dev, but PS2SDK=<project>/sdk/ps2sdk (built from sdk/src, a copy of ps2dev/ps2sdk at 39a89923 with our changes, see sdk/UPSTREAM.md). In Serena's shell first run `. sdk/env.sh` (sets PS2DEV, PS2SDK, GSKIT, PATH; vars are not set by default). Rebuild the SDK with `sdk/build.sh` (-k to keep going; install no longer touches /usr/local/ps2dev). crt0.o comes from sdk/ps2sdk/ee/startup via -B in Makefile.eeglobal. Link libmpeg with -lmpeg (fixed copy in the SDK; tools/vidtest/mpeg was deleted). IOP modules: `make all` in tools/audiotest/iop. The old /home/user/Projects/ps2sdk checkout and /usr/local/ps2dev/ps2sdk are no longer used by the engine.
- Related source trees: /home/user/Projects/ps2sdk, /home/user/Projects/gsKit
- Language: C (Serena language server `cpp`, already set in .serena/project.yml). clangd needs compile_commands.json once sources exist; see PS2Sandbox memory language_server for how to generate it.
- Emulator for testing: PCSX2 2.6.3 (pacman), /usr/bin/pcsx2-qt; config in ~/.config/PCSX2 (BIOS present: PAL v6 30004R). Run a built ELF with `pcsx2-qt -elf <file.elf>` (flag not yet verified here; `-batch`/`-nogui` also exist). GUI app: do not start from Serena shell in a way that blocks; ask the user to launch or run it detached.
- Virtual gamepad for testing in PCSX2: tools/vpad/vpad.py (uinput, device "Claude Virtual DualShock"). Run with /usr/bin/python3 (the uv python lacks evdev). `selftest` verified; `daemon` + `send "tap cross; wait 200"` use a FIFO in $XDG_RUNTIME_DIR (daemon verified 2026-10-16: start with `(setsid nohup /usr/bin/python3 tools/vpad/vpad.py daemon >/tmp/vpad.log 2>&1 </dev/null &)`, stop with `vpad.py send quit`; FIFO is /tmp/vpad.fifo when XDG_RUNTIME_DIR is unset; the user binds the pad once in PCSX2 Controller settings). Needs /dev/uinput access: user is in group uinput (udev rule /etc/udev/rules.d/99-uinput.rules).
- Screenshots (user approved, 2026-10-16): Wayland session; Serena's shell has no display vars. Use `XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0 grim <png>` (full desktop, so it also captures other windows; crop with `grim -g "x,y wxh"` when the window position is known). Save into /home/user/Projects/PS2GameEngine/.screenshots/ (connected folder), then mcp__remote-devices__device_stage_files and Read the staged copy.
- Test loop verified: run ELF in PCSX2 -> vpad send "dpad down; wait 120; dpad none" -> grim -> Read. Debug menu controls in PS2Sandbox ELF: UP/DOWN select, CROSS enter, L2 memory page, START quit.
- VM stability (2026-10-16): a full VM freeze happened while PCSX2 ran with a screenshot every ~2.3 s; VBox.log showed no error (not the earlier nested-virt Guru Meditation). Host VirtualBox was 7.2.18 vs guest additions 7.2.20 (mismatch). User then disabled VM 3D acceleration; after that two full intro playthroughs with a screenshot every 4.5 s ran without freezing. Keep capture rate low (>=4 s) and avoid long blocking shell calls (the tool wait is ~57 s: poll with sleeps under 50 s).
- Pad button mapping gotcha: SDL/PCSX2 auto-maps evdev BTN_NORTH (0x133) to PS2 Square and BTN_WEST (0x134) to PS2 Triangle, so vpad.py uses square=BTN_NORTH, triangle=BTN_WEST (fixed 2026-10-16; before that Square/Triangle were swapped and the Text Test misbehaved). L2/R2 are buttons in vpad (PCSX2 binds them to +LeftTrigger/+RightTrigger), and PCSX2 re-detects the pad after the daemon restarts.
- Audio capture (verified 2026-10-16): PipeWire. `XDG_RUNTIME_DIR=/run/user/1000 ffmpeg -f pulse -i alsa_output.pci-0000_00_05.0.analog-stereo.monitor -t 8 out.wav` records what PCSX2 plays (silence reads about -50 dB). Stage the wav with device_stage_files and analyse it in the cloud container (numpy is only there; the user machine has no numpy). Pitch/speed method: log-frequency long-term spectrum of the recording cross-correlated with the source wav; it measured the Audio Test speeds 0.33/0.5/0.75/1.0/1.25 exactly (sound playback speed is true resample, pitch shifts with speed). Keep calls short (a long shell call made the device bridge disconnect twice).
- Dpad reliability: hold dpad >=1000 ms (`dpad left; wait 1000; dpad none`) — 300-500 ms holds were mostly dropped, and RIGHT in particular rarely registered; on-screen overlays/screenshots can lag, so confirm state from the PCSX2 log (`grep -a "audio_test\] playing" ~/.config/PCSX2/logs/emulog.txt | tail -1`). vpad.py daemon now survives bad commands (it used to die on `tap up`; dpad directions are `dpad ...`, not `tap`).
- Input reliability: some pad taps were dropped at 100 ms hold (and a START right after other taps); use `tap <button> 250` and verify the result on screen.
- Game window position changes after a reboot: re-find it with one full-screen grim shot, then update the -g region in tools/vpad/shot.sh (currently "1313,79 770x668").
- Test scripts used /tmp/introrun/{intro.sh,sheet.py} (volatile): intro.sh enters Intro Test, picks the language, grabs frames; sheet.py builds 3x3 contact sheets with Pillow (/usr/bin/python3 has PIL).
